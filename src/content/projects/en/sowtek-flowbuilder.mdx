## Problem

Every contact centre wants its own IVR, its own routing rules and its own bot flows, and wants to change them without waiting for an engineering release. Hard-coding each client's flows does not scale; giving them a general-purpose automation tool does not understand calls, queues and agents.

## Constraints

- **Domain nodes**: Answer, IVR, Queue, Direct Agent, Say Digits, Text-to-Speech, Call Back, Database, Email: the building blocks of a contact centre, not generic HTTP steps.
- **One engine for calls, chat and SMS**.
- **Safe changes**: a flow is drafted, simulated, then published, and a live call never runs a half-edited flow.
- **Runs next to real-time traffic**: flow steps execute while a caller is waiting.

## Key decisions

1. **Domain-specific nodes over generic steps.** Supervisors think in IVRs and queues, so the nodes are IVRs and queues.
2. **Publish, don't edit live.** Each interaction runs one published version from start to end.
3. **Simulation is part of the builder.** A flow can be walked through before any customer hears it.
